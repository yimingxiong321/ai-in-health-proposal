\section*{Problem}
Clinical LLM agents can diagnose patients and, between encounters, revise a persistent
\emph{skill library} instead of their weights. In our prior work (\textsc{DxSkill},
submitted to ACL ARR), a student agent revising its own skills on MIMIC-CDM improves from
77.5\% to 86.9--89.1\% accuracy depending on feedback, and a stronger reviser helps mainly
when outcome feedback is weak. We also found skill revision is \emph{not} reliably safe:
a useful skill can be silently deleted, and a transient tool error can be hardened into a
harmful permanent restriction, even with outcome feedback available. These two findings
motivate two \emph{independent} follow-up tracks (A and B), not one combined study.
\textbf{A} (inspired by OpenAI's 2023 weak-to-strong generalization work): can a weaker
model teach a stronger diagnostic agent, not by supervising its predictions directly, but
by authoring/maintaining the skill library the strong model executes? Crossing diagnoser
and reviser strength separates task-execution ability from reflection/knowledge-organization
ability. \textbf{B}: can skill revision be made safer by validating each proposed update on
a holdout buffer before committing it, so useful skills aren't deleted and transient errors
aren't hardened into permanent restrictions?

\section*{Data and access}
MIMIC-CDM 1.1 (from MIMIC-IV): 250 training / 400 held-out patients across appendicitis,
cholecystitis, diverticulitis, pancreatitis. We already have data access (completed MIMIC
training) and a working pipeline (diagnosis tools, reflection/revision loop, checkpointed
libraries), so no new access is needed.

\section*{Approach and baselines}
\textbf{A — weak-to-strong transfer.} Baseline: DxSkill's student-self-revises condition
(86.9\%) and teacher-edits-weak-student condition (Qwen3.8-27B revises, Qwen3-30B-A3B
diagnoses). New: a diagnoser-strength $\times$ reviser-strength grid (\{weak,strong\}
$\times$ \{weak,strong\}) under fixed reference-diagnosis feedback. The weak-revises-strong
cell is the key new condition.
\textbf{B — validation-buffer gating.} Baseline: DxSkill's current ungated revision. New:
after each proposed update, evaluate the candidate library on a small fixed holdout buffer
(disjoint from the 400-patient eval set) before committing; accept only if buffer accuracy
doesn't regress beyond tolerance $\varepsilon$, else roll back to the prior checkpoint.

\section*{Evaluation}
\textbf{A:} accuracy on the frozen 400-patient set per diagnoser$\times$reviser cell
(paired patient-bootstrap intervals, as in our ACL ARR submission), to locate where
weak-to-strong transfer helps or fails.
\textbf{B:} buffer-set accuracy per checkpoint to track accept/reject decisions; held-out
accuracy with vs.\ without the buffer; qualitative tracing of accepted/rejected edits,
counting how often the buffer blocks a harmful edit or preserves a useful one (cf.\ our
Figure 7 case).
