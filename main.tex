\section*{Problem and why it matters}
Language-model clinical agents can diagnose patients and, between encounters, revise a
persistent \emph{skill library} instead of their weights. In our prior work (\textsc{DxSkill},
submitted to ACL ARR), a student agent that revises its own skills on
MIMIC-CDM improves from 77.5\% to 86.9--89.1\% accuracy depending on the feedback it
receives, and a stronger reviser only helps when outcome feedback is weak. We also found
that skill revision is \emph{not} reliably safe: a useful skill can be silently deleted,
and a transient tool error can be hardened into a harmful permanent restriction, even
though outcome feedback was available throughout. These two observations motivate two
separate, independent follow-up questions, which we treat as two separate experiment
tracks (Direction A and B below), not one combined study.
\textbf{Direction A} (inspired by OpenAI's 2023 weak-to-strong generalization work) asks:
\textit{can a weaker model teach a stronger diagnostic agent not by supervising its
predictions directly, but by authoring and maintaining a reusable skill library that the
strong model then executes?} Crossing diagnoser and skill-reviser strength lets us
separate two abilities normally entangled in a single model: raw task execution versus
reflection and knowledge organization. \textbf{Direction B} asks: \textit{can we make
skill revision itself safer}, by validating each proposed update on a holdout buffer
before committing it, so that useful skills are not silently deleted and transient
errors are not hardened into permanent restrictions?

\section*{Data and access}
MIMIC-CDM 1.1 (derived from MIMIC-IV), the benchmark used in our ACL ARR submission:
250 training and 400 held-out patients across appendicitis, cholecystitis, diverticulitis,
and pancreatitis. We already have data access (completed MIMIC training) and a working
pipeline (diagnosis tool interface, reflection/skill-revision loop, validation and
checkpointed skill libraries), so no new access is required.

\section*{Approach and baselines}
We pursue two independent extensions of DxSkill, each with its own baseline; they share
the codebase and benchmark but address different questions and are evaluated separately.

\textbf{Direction A: weak-to-strong skill transfer.} Baseline: the existing DxSkill
student-revises-its-own-skills condition (86.9\% accuracy) and the existing
teacher-edits-weak-student condition (Qwen3.8-27B revises, Qwen3-30B-A3B diagnoses). New
approach: extend this into a reviser-strength $\times$ diagnoser-strength grid, \{weak,
strong\} diagnoser crossed with \{weak, strong\} reviser, holding feedback
(reference diagnosis) fixed. The new weak-to-strong cell (weak reviser edits skills,
strong model diagnoses) is the key condition, isolating whether gains depend on task
execution strength or on reflection/knowledge-organization strength.

\textbf{Direction B: validation-buffer gating.} Baseline: DxSkill's current ungated
skill revision, which we showed can silently delete a useful skill or harden a
transient tool error into a permanent restriction. New approach: after each training
case's proposed skill update, evaluate the candidate library on a small, fixed holdout
buffer set (disjoint from the 400-patient evaluation set) before committing it; accept
the update only if buffer accuracy does not regress beyond a tolerance $\varepsilon$,
otherwise roll back to the previous checkpointed library.

\section*{Evaluation}
\textbf{Direction A:} diagnostic accuracy on the frozen 400-patient held-out set for
each diagnoser$\times$reviser cell, using paired patient-bootstrap intervals as in our
ACL ARR submission, to locate where weak-to-strong transfer helps or fails.
\textbf{Direction B:} buffer dev-set accuracy at each checkpoint to track accept/reject
decisions over training; held-out accuracy with vs.\ without the buffer; and qualitative
tracing of accepted vs.\ rejected edits, counting how often the buffer blocks a harmful
edit or preserves a previously useful skill (cf.\ our Figure 7 case).
