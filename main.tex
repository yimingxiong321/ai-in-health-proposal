\section*{Problem and why it matters}
Clinical LLM agents can diagnose patients and, between encounters, revise a persistent
\emph{skill library} instead of their weights. In our prior work (\textsc{DxSkill},
submitted to ACL ARR), a student agent that revises its own skills on MIMIC-CDM improves
from 77.5\% to 86.9--89.1\% accuracy depending on the feedback it receives, and a stronger
reviser helps mainly when outcome feedback is weak. We also found that skill revision is
\emph{not} reliably safe: a useful skill can be silently deleted, and a transient tool
error can be hardened into a harmful permanent restriction, even when outcome feedback is
available throughout. These two findings motivate two separate follow-up questions, which
we treat as two \emph{independent} experiment tracks (Directions A and B below), not one
combined study.

Direction A (inspired by OpenAI's 2023 weak-to-strong generalization work) asks: \emph{can
a weaker model teach a stronger diagnostic agent, not by supervising its predictions
directly, but by authoring and maintaining a reusable skill library that the strong model
then executes?} Crossing diagnoser and skill-reviser strength lets us separate two
abilities normally entangled in a single model: raw task execution versus reflection and
knowledge organization. Direction B asks: \emph{can we make skill revision itself safer},
by validating each proposed update on a holdout buffer before committing it, so that
useful skills are not silently discarded and transient errors are not hardened into
permanent restrictions?

\section*{Data, and whether we have access}
We use MIMIC-CDM 1.1 (derived from MIMIC-IV): 250 training patients and 400 held-out
patients across appendicitis, cholecystitis, diverticulitis, and pancreatitis. We already
have data access (the team has completed the required MIMIC data-use training) and a
working experimental pipeline from DxSkill (diagnosis tool interface, reflection/
skill-revision loop, and checkpointed skill libraries), so no new access or infrastructure
is needed to begin either direction.

\section*{Approach and baselines}
\textbf{Direction A -- weak-to-strong skill transfer.} Baseline: the existing DxSkill
student-revises-its-own-skills condition (86.9\% accuracy) and the existing
teacher-edits-weak-student condition (Qwen3.8-27B revises skills, Qwen3-30B-A3B
diagnoses). New approach: extend this into a full diagnoser-strength $\times$
reviser-strength grid, \{weak, strong\} diagnoser crossed with \{weak, strong\} reviser,
holding feedback (reference diagnosis) fixed throughout. The new weak-revises-strong
cell is the key condition we have not yet tested.

\textbf{Direction B -- validation-buffer gating.} Baseline: DxSkill's current ungated
skill revision. New approach: after each training case's proposed skill update, evaluate
the candidate library on a small, fixed holdout buffer set (disjoint from the 400-patient
evaluation set) before committing it. We accept the update only if buffer accuracy does
not regress beyond a tolerance $\varepsilon$; otherwise we roll back to the previous
checkpointed library.

\section*{How we'll evaluate it}
\textbf{Direction A:} diagnostic accuracy on the frozen 400-patient held-out set for each
diagnoser$\times$reviser cell, using paired patient-bootstrap intervals as in our ACL ARR
submission, to locate where weak-to-strong transfer helps and where it fails.
\textbf{Direction B:} buffer-set accuracy at each checkpoint to track accept/reject
decisions over training; held-out accuracy with vs.\ without the buffer; and qualitative
tracing of accepted vs.\ rejected edits, counting how often the buffer blocks a harmful
edit or preserves a previously useful skill (cf.\ our Figure 7 case).
